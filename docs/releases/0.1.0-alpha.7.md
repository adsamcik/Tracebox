# Tracebox 0.1.0-alpha.7

## Release scope

Alpha.7 hardens fatal and degraded-runtime behavior needed by Tracker: repeated OOM,
stack overflow, native-handler death, physical storage pressure, and bounded process-exit history
across every process in the application UID.

## Highlights

- OOM capture selects a prebuilt type-only structural record. It does not walk causes or frames,
  allocate a per-thread recursion guard, or persist an exception message.
- Stack overflows retain a bounded structural stack when possible and fall back to a prebuilt
  type-only record if capture itself cannot proceed.
- Managed-crash flags distinguish cause cycles, OOM, stack overflow, and reduced capture without a
  schema or package-format change.
- `ApplicationExitInfo` reconciliation imports bounded structural metadata for ANR, low-memory,
  managed/native crash, signaled, dependency, user-requested, and other documented OS reasons.
  Source keys include process identity fields, so repeated exits and separate app processes remain
  distinct and idempotent.
- Non-ANR exits never claim or open a raw artifact. ANR raw traces retain the existing exact policy
  token, size bound, journal, and cleanup requirements.
- Every service disconnect/dead/null binding withdraws native readiness immediately. Callback
  storms coalesce into one serialized recovery attempt while the existing observer remains a
  fallback.
- A physical write failure or unavailable UID quota ledger opens a storage-pressure circuit:
  ordinary writes stop, readiness degrades, fatal summaries remain in the fixed memory buffer, and
  one retry is allowed at a later foreground boundary or explicit policy application.

## Compatibility and privacy

The public `tracebox-core` JVM record now exposes `JvmFatalKind` plus a `reduced` marker. Existing
constructors remain source-compatible through defaults. The generated event schema fingerprint,
deterministic `.tbdiag` v1 format, privacy classes, approved-package lifetime, native ABI inputs,
and no-network boundary are unchanged.

## Published modules

The release publishes `tracebox`, `tracebox-api`, `tracebox-core`, `tracebox-storage`,
`tracebox-directboot`, `tracebox-anr-exit`, `tracebox-export`, `tracebox-export-ui`,
`tracebox-native`, and `tracebox-ui-compose`.

## Qualification

The exact release source must pass the complete host-readiness and release-content task sets.
Focused tests additionally prove 32 sequential OOM captures with exact prior-handler chaining,
bounded stack-overflow frames, distinct repeated/multiprocess exit keys, metadata-only raw-artifact
rejection, handler-death coalescing, storage-pressure retry state, and crash-buffer restoration.

## Tracker consumption

Use `0.1.0-alpha.7` only after immutable publication. Tracker should pin the published artifacts
and verification metadata; isolated candidate repositories are disposable validation seams and
must not be used by production or CI.
